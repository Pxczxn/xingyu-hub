# 历史重构辅助脚本（归档）

本目录归档的是「星语 Legacy」开发过程中的**历史重构辅助脚本**。它们被保留主要用于**历史追溯**，而不是作为未来日常开发的工具。

> ⚠️ 这些脚本**不是日常开发工具**。请勿在重构/新功能开发中直接依赖或重新运行它们。

## 包含脚本

| 脚本 | 原始用途 | 风险 |
|------|----------|------|
| `delete-deprecated-pages.mjs` | v4.1 路由重构期间，按清单删除 `xingyu-web/app` 下一批已废弃页面（users/、studio/*、messages/*、tags、hot、me/* 等） | **破坏性**：直接 `unlink` + `rmdir`，无 dry-run、无确认保护；重跑会再次删除真实文件 |
| `replace-user-links.mjs` | v4.1 路由重构期间，把前端 `.tsx` 中的 `/users/...` 链接批量改写为 `/u/...` | **改写源码**：直接 `writeFile` 覆盖源码，无 dry-run、无确认保护 |

## 重要说明

1. **这些是历史重构辅助脚本**：它们服务于某一次具体的重构任务，不代表当前或未来的工程规范。
2. **并非日常开发工具**：不要把它们当作脚手架、CLI 或通用工具来使用。
3. **部分操作具有破坏性**：`delete-deprecated-pages.mjs` 会直接删除文件；`replace-user-links.mjs` 会直接覆盖源码。两者都**没有提供完整的 dry-run / confirmation 保护**。
4. **未提供完整保护**：脚本在运行前不会列出将要影响的范围，也不会要求二次确认。
5. **禁止 AI 或开发者未经代码审查直接运行**：任何运行都必须先由人工阅读脚本内容、确认目标路径与当前仓库结构仍然匹配，并通过代码审查。
6. **保留目的主要是历史追溯**：它们用于理解某次重构“做过什么”，而不是为了在未来“再执行一次”。如确有复用价值，应先复制到独立工具目录并补齐 dry-run / 确认 / 测试后再使用。

## 处理方式

- 这些脚本保留在仓库中，但位于 `maintenance/legacy-scripts/`，与 `scripts/` 下的正式维护工具隔离。
- 它们**未经修改以重新适配当前结构**——这是“归档”，不是“恢复可用”。
